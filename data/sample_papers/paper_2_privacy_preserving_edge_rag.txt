# Zero-Telemetry Offline Document Intelligence: Architectural Design and Privacy Benchmarking for Edge Computing

**Authors**: Dr. Sophia Lindqvist, Tariq Al-Mansoor, Dr. Helena Vogel
**Affiliation**: Institute for Secure Computing & Applied Cryptography, Zurich
**Date**: January 2025

---

### Abstract
Modern conversational AI tools frequently necessitate transmitting confidential enterprise and scientific documents to remote hyperscale cloud providers. This architectural reliance introduces significant threat surfaces, including eavesdropping, third-party data retention, training set contamination, and regulatory non-compliance with GDPR and HIPAA frameworks. In this paper, we introduce **PrivacyPilot-Edge**, an air-gapped, zero-telemetry document intelligence architecture that executes 100% locally on personal computing endpoints. By coupling a local FAISS vector store with local instruction-tuned models, PrivacyPilot-Edge guarantees zero network egress while retaining citation-level verifiability. In our adversarial penetration tests and network packet auditing, the system exhibited exactly zero outbound network packets during ingestion, vector indexing, semantic search, and generation tasks.

---

### 1. Introduction & Problem Definition
The proliferation of proprietary document repositories in scientific research, clinical trials, and defense engineering mandates robust data sovereignty. When researchers query documents using centralized AI services, the documents are decrypted in transit and in memory on multi-tenant server infrastructure.

To solve this vulnerability, edge computing architectures must provide local storage, local embeddings, and local inference on the host device. Privacy cannot merely be an organizational promise; it must be enforced by mathematical and architectural isolation.

---

### 2. Threat Model & Privacy Guarantees
We define our security boundary around the local PC host running Windows on ARM64 / Snapdragon platforms:

- **Threat 1: Cloud Eavesdropping**: Eliminated via complete removal of remote API calls. All embedding models and generative LLMs are stored on the local encrypted filesystem.
- **Threat 2: Index Contamination**: Local FAISS vector indices are stored in user-controlled application data directories without telemetry callbacks.
- **Threat 3: Hallucination & Citation Forgery**: The RAG pipeline employs deterministic citation tagging, enforcing that every generated assertion maps to an exact document ID, page number, and chunk offset.

---

### 3. Architecture & Ingestion Pipeline
The zero-telemetry pipeline consists of:
1. **Local Document Loader**: Securely parses PDF, TXT, and DOCX formats without external rendering engines.
2. **Deterministic & ONNX Embedding Generators**: Runs on-device embedding extraction using fixed-point vector projections.
3. **Local Vector Database**: Serializes indexed document chunks into isolated binary FAISS indices on the host NVMe SSD.
4. **Local Synthesis Engine**: Performs grounded retrieval without communicating with cloud LLM APIs.

---

### 4. Empirical Evaluation & Network Audit
We audited network traffic during the ingestion of 1,000 confidential biomedical clinical reports using Wireshark packet capture across 24 hours of continuous operation:

- **Inbound Data (Internet)**: 0.00 KB
- **Outbound Data (Internet)**: 0.00 KB
- **Local Host Memory Resident**: 100%
- **Disk Storage Overhead**: 4.2 MB per 100 pages of text.
- **User Document Deletion Latency**: < 5 milliseconds to purge from disk and memory.

---

### 5. Research Findings & Usability
Our user study with 45 academic researchers demonstrated that 96% of participants favored local offline RAG over cloud alternatives when working with unpublished manuscripts and patent applications. Latency remained consistently under 180 ms per query, enabling real-time interactive literature review without network dependencies.

---

### 6. Limitations & Future Work
The primary constraint of local air-gapped architectures is initial model installation, which requires an initial local artifact setup or pre-installed OEM image. Future work will investigate differential privacy guarantees for multi-device local mesh synchronization over local-area Bluetooth and Wi-Fi Direct.
